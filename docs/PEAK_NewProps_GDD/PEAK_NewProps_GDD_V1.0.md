## 1. 需求背景、体验目标与设计原则

### 1.1 背景与产品适配

《PEAK》的基础体验围绕高差攀登、体力管理、携带负重、物理交互、多人协作及雨水等环境危害。热带雨林中，雨水会使露天岩面湿滑，增加攀爬体力成本并降低稳定性；普通手持物品会阻碍抓墙，原生岩钉提供固定休息点。因此新增道具必须构成**有边界的路线选择**，而非永久删除环境挑战或无限体力漏洞。

### 1.2 玩家体验目标

| 编号 | 体验目标 | 可观察的玩家行为 | 失败表现 |
|---|---|---|---|
| GO-01 | 烘干创造短时团队窗口 | 队友选择烘干时机，连续通过湿岩壁 | 雨中永久干燥或一喷即复湿 |
| GO-02 | 烘干可跨自然转角 | 同一连通岩壁的相邻表面被影响 | 隔着薄墙烘到背面 |
| GO-03 | 吸盘改变可选路线 | 玩家从竖直墙转入头顶岩面绕行 | 头顶岩面无限吸附一切材质 |
| GO-04 | 恢复体力但保留代价 | 玩家在一次连续吸附中最多恢复 20 点，持续移动仍耗体力 | 无限悬挂恢复满体力、每帧重复扣次数 |
| GO-05 | 输入反馈直观 | 成功才扣次数，无效目标有明确提示 | 空挥浪费、最后 1 次吸附成功后立即跌落 |
| GO-06 | 保持合作与资源权衡 | 重量、槽位、篝火补充、队友共享共同影响路线决策 | 无限篝火刷充能、背包复制道具 |

### 1.3 设计原则

1. **一物一核心收益**：烘干机改造危险岩面；吸盘扩展可攀地形并提供有限体力恢复。
2. **输入一致、例外显式**：沿用原版交互，吸盘作为“持物仍能抓墙”的特殊例外，其他手持物品不因此开放攀爬。
3. **资源不凭空增长**：每次使用与充能必须有可审计状态；多人只能获得同一个真实结果。
4. **反馈先于误解**：目标有效、剩余次数、湿岩剩余时间、吸附状态都必须在 UI 和 VFX 中可辨。
5. **不破坏物理与关卡**：不得穿墙、穿过不可抓岩面或绕过既有天气系统；表现不改变碰撞求解。

### 1.4 需求范围与不做项

**包含**：两件道具的拾放收纳、蓄力投掷、使用次数与销毁、烘干区与雨水交互、篝火充能、吸盘特殊攀爬、体力恢复、倒悬移动、跨角过渡、多人同步、UI/VFX/SFX、测试关卡与验收。

**不包含**：跳床；新增角色属性或常驻天赋；永久干燥岩面；其他道具的改版；完整天气系统重写；不受限制的抓墙传送；独立的新背包 UI。对 PEAK 原版具体内部实现、控制器/网络类名不作未经证实的假设。

## 3. 通用交互、库存与状态优先级

### 3.1 输入映射与冲突处理

| 输入 | 未持物/普通状态 | 手持烘干机 | 手持吸盘 |
|---|---|---|---|
| E | 按游戏原交互拾取 | 对可交互目标按常规 E | 同左 |
| LMB 按下 | 普通抓墙 | 有合法目标时触发一次烘干 | 建立一次吸附，成功才扣 1 次 |
| LMB 持续按住 | 保持抓墙 | 不重复扣次数/不连发 | 维持已建立的吸附会话 |
| LMB 松开 | 松手 | 无附加使用 | 退出吸附会话；若空中则下落 |
| Tab | 常规收纳 | 收入普通物品槽；满格按原系统反馈 | 同左；吸附进行中不允许收纳导致瞬间脱离 |
| Q 轻按 | 原物品丢弃 | 放到物理世界，不触发烘干 | 放到物理世界，不触发吸附 |
| Q 长按释放 | 原投掷曲线 | 根据时长蓄力投掷 | 同左；进行中的吸附优先安全解除/禁止投掷 |
| WASD | 正常移动 | 受游戏持物移动规则 | 吸附后沿当前合法表面移动 |
| Shift | 现有冲刺/快爬 | 不增加额外特权 | 移动中按原攀爬规则处理，不享受免费快爬 |

**判定优先级**：全局暂停/死亡 > 已建立的吸附会话的继续/解除 > 本次道具合法使用 > 普通抓墙 > 拾放/收纳/投掷。禁止一帧内同时处理“扣使用次数”与“丢弃物品”两个相互冲突的事务。

### 3.2 对失败操作的通用定义

无效目标、超出射程、无有效岩面、场景被遮挡、次数已耗尽、背包满格或网络验证失败时：**不消耗使用次数，不施加效果**。UI 告知最直接原因；不得在客户端先扣再悄悄不同步。

### 3.3 物品生命周期

`WorldPickup → Held → Stored(Regular/Backpack) → Held → Using/Active → Held 或 Consumed`；丢弃/投掷从 `Held` 回到 `WorldPickup`。所有节点必须保存道具实例 ID、剩余次数和特殊限制数据。消耗销毁应从物理世界、手持显示、物品槽和网络实体中一致移除，不能留隐形碰撞体。

## 4. 便携烘干机详细规则（P0）

### 4.1 玩法描述

玩家手持烘干机，瞄准需要处理的湿滑岩石表面按 LMB，立即使命中点附近可连通的 **7m×7m** 岩面区域暂时恢复正常攀爬属性。每次有效烘干持续 **20 秒**；倒计时结束后由当前环境规则决定是否再次湿滑。效果适用于所有队友。

### 4.2 一次使用的完整流程

`手持 → 瞄准 → 射线检测合法岩面 → 提取连通表面作用域 → 验证存在有效烘干/刷新目标 → 服务器/权威端确认 → 扣除 1 次 → 施加20s局部烘干状态 → VFX/SFX/HUD → 倒计时 → 还原天气主导权`

- **触发条件**：持有烘干机、剩余次数 ≥1、瞄准合法岩面、在射程内、存在至少一个需烘干的湿面单元，或存在可由本次合法使用刷新的烘干单元；网络端验证成功。
- **执行**：计算仅在岩面连接图内可到达的区域，对满足规则的单元设 `DryUntil = Now + 20s`；若已有生效倒计时，刷新至本次的 20 秒，不累计延长。
- **退出**：播放结束 VFX；倒计时走完，移除该临时豁免；湿度由原天气系统重新判定。
- **异常**：范围内仅有干岩石且无活跃待刷新的合法效果时，不扣次数；对非岩石、空中、队友、被遮挡的背面使用也不扣次数。

### 4.3 连通岩面传播规则（重点）

**策划判定**：烘干机不能以世界坐标球形范围直接修改所有 Collider。以击中表面为种子，只沿属于同一可传播岩石网络的表面片区扩散；允许跨 90° 内/外转角及其他自然相接岩面；不穿越实心岩石、不跨越空气间隙、不传播到无连通边的邻近表面。

**7m×7m 定义**：以命中点为中心，在连通岩面“局部展开坐标”中形成宽 7m、高 7m 的目标区域，中心到每个轴向边界为 3.5m；遇边角时将局部坐标沿表面邻接关系连续展开。总有效面积不超过约 49m²（边界裁剪及离散精度允许误差），不能因连通分叉让多面各自重复获得完整 7×7。该定义由程序与 TA 以可视化 Debug Mask 联调验收。

**建议技术实现（非策划强制算法）**：为每个湿度可控岩石片区建立表面图节点及共享边邻接；从命中三角面/片区沿网格邻接遍历并传播二维局部坐标，裁剪到有效面积掩码；对候选覆盖执行材质标签及实体遮挡/穿墙校验。复杂不规则岩面可用离散采样近似，但不得出现肉眼明显隔墙生效。

### 4.4 湿滑与天气优先级

| 场景 | 生效期间 | 20秒结束后 |
|---|---|---|
| 持续下雨且岩石暴露 | 当即消除湿滑减益，恢复普通攀爬参数 | 立即按正在生效的雨水规则重新湿滑 |
| 雨停且岩面自然仍潮湿 | 当即消除湿滑减益 | 按原环境干燥演算结果处理，不强制回湿 |
| 已干燥岩石 | 不变化；纯无效目标不耗次数 | 保持原环境结果 |
| 与新烘干范围重叠 | 已覆盖单元的截止时间刷新为本次 Now+20s | 各单元按最新合法截止时间结束 |
| 多名玩家接连使用 | 全队共享最新区域状态；每次合法使用各扣 1 次 | 不叠加多层增益、不无限延时 |

对于**已经在湿岩上攀爬的玩家**，烘干生效的下一次物理/规则更新起恢复正常攀爬消耗；20 秒结束仍在岩壁的玩家即时重新承受天气减益，不给予额外离场宽限。【规则补全】

### 4.5 篝火充能与次数

- **初始/上限**：3/3；单次有效使用 -1；变为 0 的瞬间移除该道具实例。【已定】
- **前置**：烘干机剩余 **1 或 2 次**；目标是一个**已点燃**的有效篝火；当前道具实例没有使用过该篝火的充能机会。【已定】
- **结果**：`NewUses = min(3, OldUses + 2)`；因此 1→3、2→3，绝不突破 3。【已定】
- **次数限制**：同一**道具实例 ID × 篝火实例 ID**最多成功充能一次；同一篝火可为另一台不同实例烘干机充能。【已定】
- **失败不占次数**：满电、0 次已消失、未点燃、射程不够、重复充能时不消耗该篝火机会。
- **物品身份**：放下、投掷、给队友、收入 Backpack、断线重连后，其已用过的篝火 ID 集合不得重置。
- **避免系统冲突**：烘干机与篝火的“充能”必须被识别为该道具专属交互，不走其他物品可能具有的烹饪/焚毁逻辑。【设计例外】

## 5. 吸盘详细规则（P0）

### 5.1 定位与例外

吸盘属于**唯一允许“手持本体时维持攀爬”的特殊道具**。普通手持物仍遵循 PEAK 的常规攀爬限制；吸盘必须明确标记 `CanClimbWhileHeld = true`，避免把普通装备也开放为双手抓墙。

吸盘可用于合法常规岩面及经标记允许的头顶/倒悬岩面。它并非把玩家完全固定为不可移动的静态物体，而是暂时提供可控的表面约束和移动方向；真实碰撞、重力和外力反作用仍然存在。

### 5.2 成功吸附及扣次规则

- **初始次数/上限**：15/15；重量 3，占 1 格；允许进入 Backpack。【已定】
- **输入**：手持吸盘并按住 LMB；只有成功建立一个新吸附会话才扣 1 次。【已定】
- **成功前置**：次数 ≥1；目标表面具有可吸附标记；距离、角度、碰撞空间和网络校验全部通过。失败不扣次。
- **一次会话的定义**：从第一次合法吸附成功到玩家松开 LMB、角色死亡/失能、道具被强制移除或表面失效而真正脱离为止。原地悬挂、持续横移、跨内外角、墙面转头顶**均不重复扣次**。
- **一次会话中 LMB 始终按住**；松手立即解除约束并按现有物理系统处理下落，不要求玩家额外按键确认。
- **最后一次**：从 1→0 时这一次成功建立的会话**继续有效**；道具标记 `DestroyAfterRelease=true`，会话结束才从库存和手持模型中消失；不能在本次会话中重复创建另一条新会话。

### 5.3 攀爬中的装备切换冲突解决

**问题**：普通规则下手持物品不能抓墙，而需求又包含“攀爬途中启用吸盘”。

**最终规则**：玩家可以在正常攀爬状态下选择常规快捷物品槽中的吸盘，进入一次**有限的抓握交接窗口**；切换过程中原有抓墙约束不因切换动画而提前解除，LMB 持续按下且新吸附合法时转入 `SuctionAttached` 并扣 1 次。若吸附失败，不扣次数且保持原有抓附判定；玩家主动松开 LMB 则正常坠落。该交接仅开放吸盘，且不得借此免费重置体力或无敌。【从原设计推导的必要例外】

从地面或空中持吸盘按住 LMB，也可以在合法距离与朝向内直接建立新会话。把吸盘放在 Backpack 中时不能直接隔空使用，应先按原有存取流程取出。

### 5.4 静止恢复体力与移动消耗

**开始计入恢复预算**：成功建立吸附会话之后，记录 `RecoveredThisSession = 0`。只有在 `SuctionAttached` 且没有有效方向输入、吸附仍有效时，按玩家正常休息恢复速率缓慢恢复体力；累计恢复量最多 **20 点**。【已定】

具体规则：

| 状态 | 体力变化 | 是否消耗新次数 |
|---|---|---|
| 已成功吸附，未按方向键，恢复预算未满 | 以普通走路/静止的恢复速率回复，累计至多 +20 | 否 |
| 已成功吸附，未按方向键，预算已满 | 停止恢复；维持附着不再额外扣“悬挂耗体力” | 否 |
| 已成功吸附，WASD 有有效运动意图 | 按当前表面类型适用的普通攀爬/快爬规则消耗体力 | 否 |
| 转角/墙转天花板，LMB 连续保持 | 运动时计正常攀爬成本；不停会话 | 否 |
| 松开 LMB | 解除吸附，按坠落规则处理 | 不追加；如余次 0 则销毁 |
| 再次合法吸附 | 新建会话，恢复预算重新开始 | 是，-1 |
| 仅按 LMB 但未吸附成功 | 不进入恢复状态；不扣次数 | 否 |

**体力上限**：不能突破当时的有效体力上限；若当前上限剩余空间不足，最多补到上限，未用的恢复预算不自动转移下一会话。体力恢复不直接治愈受伤、寒冷、饥饿或其他负面状态。

**关于外力**：没有方向键不代表角色可以无视一切外力；若受到超出吸附承载力的冲击、吸附点失效或角色死亡，则正常脱离，不继续恢复。承载力阈值【建议】由物理程序配置。

### 5.5 头顶岩石与表面过渡（核心差异）

- **合格表面**：`SuctionAllowed` 且为实体岩石表面；近似水平的朝下岩面、合法倒悬岩面及与其连续连接的竖直岩壁。不可抓空气、普通可拾取物、未标记装饰石、角色本体或强制禁攀障碍。
- **运动坐标**：在当前表面切平面建立局部二维移动方向；A/D、W/S 相对于可理解的镜头/表面参考方向映射。墙→天花板→邻面切换时保持输入连续，不自动反转 A/D。
- **转场**：以合法相邻表面与胶囊安全轨迹进行连续过渡，维持同一次吸附会话，不追加扣次；不得直接穿过岩石让身体瞬移到天花板背面。
- **相机**：保持可读的重力“上”方向，不得在进入头顶岩面时瞬间把镜头翻转 180°；角色表现层可变化，物理 Collider 仍以碰撞安全优先。
- **上限**：未持吸盘时，头顶不可抓岩石仍保持原始不可抓规则；道具不能永久修改关卡表面是否可攀爬。
- **停止/失败**：若抓附目标突然消失、松 LMB、超过最大附着能力或碰撞路径阻塞，安全进入正常下落状态。

### 5.6 吸盘状态机

| 当前状态 | 触发 | 目标状态 | 动作 |
|---|---|---|---|
| HeldReady | LMB + 合法岩石 + 次数>0 | SuctionAttached | 原子扣 1，创建会话、恢复预算清零 |
| HeldReady | LMB + 不合法/超距 | HeldReady | 不扣次，反馈失败原因 |
| NormalClimb | 选择吸盘、维持抓附并成功交接 | SuctionAttached | 原约束交接到吸盘，扣 1 |
| SuctionAttached | 无方向键 | SuctionResting | 不掉落；累积恢复预算最多 20 |
| SuctionResting | 开始移动 | SuctionMoving | 恢复停止，按攀爬耗体力 |
| SuctionMoving | 停止移动 | SuctionResting | 在余额内继续缓慢恢复 |
| SuctionAttached / Resting / Moving | 松开 LMB / 强制脱离 | Falling / Ground | 释放附着；0 次时移除物品 |
| HeldReady（未附着） | Q / Tab | WorldPickup / Stored | 保留余次 |

### 5.7 与岩钉的差异化

岩钉是部署在固定位置的**共享或固定休息抓点**，且可在抓住时恢复体力；吸盘是**单人、手持、有限会话**的可移动攀爬工具。吸盘专长在天花板和跨表面路线；恢复收益被单次 +20 封顶，不应替代岩钉作为无限恢复站。两者的具体稀有度及掉落权重需在关卡和数值 Playtest 后配置，不在本案凭空指定。

### 8.1 推荐数据结构（接口示意）

- `ItemInstance`: `itemInstanceId`, `itemType`, `usesRemaining`, `ownerPlayerId`, `inventoryLocation`, `consumed`。
- `DryerRechargeHistory`: `itemInstanceId`, `usedCampfireInstanceIds[]`。
- `DryPatch`: `patchId`, `sourceUseEventId`, `coveredSurfaceCells[]`, `dryUntilServerTime`。
- `SuctionSession`: `sessionId`, `itemInstanceId`, `playerId`, `activeSurfaceId`, `recoveredThisSession`, `destroyAfterRelease`。
- `ClimbSurfaceData`: `surfaceId`, `suctionAllowed`, `rockSurface`, `wettable`, `adjacentEdges[]`, `blockingGeometry`。

**接口底线**：由权威端最终确认使用成功；客户端可先预览，但不能自行提交扣次/永久湿度结果。所有使用请求附请求 ID，重复网络包不可重复扣费/恢复。

### 8.2 实现建议与性能预算

- 烘干范围查询只有**使用时**执行，不要每帧扫描全场 Mesh；缓存连通拓扑，岩面更新只广播被改变的面片/区域 ID。
- 岩面 7×7 展开遇多分支时必须有“总面积上限”；大 Mesh 需要区块裁剪与 LOD/采样策略。
- 吸盘追踪应把表面坐标系、角色表现朝向、物理 Collider 解耦；保持墙转天花板时输入连续。
- 网络与存档应由稳定实例 ID 标识篝火/道具，而不是临时 GameObject InstanceID。
- 设定阶段性性能目标【建议】：单次烘干查询不造成可感知的游戏卡顿；具体 CPU 毫秒预算与人数规模经程序基准测试确定。

### 11.4 最终验收门槛

- P0 规则与阻断级 QA 用例全部通过；多人状态不存在重复扣次、物品复制、无限体力或穿墙问题。
- UI 数字与权威道具实例一致；天气生效/解除正确；任何无效使用均不能扣道具次数。
- 支持至少一个**雨天转角湿岩案例**和一个**竖墙→倒悬顶面案例**的连续无人工修复演示。
- 有明确性能日志、失败原因日志、测试录像和版本/配置记录；P1 表现问题可记录排期但不得掩盖核心状态错误。
