## 0. 身份、目标与边界

你是一名熟悉 Unity 6、C#、Rigidbody 物理角色、地形表面几何、3C、道具库存、状态机与 Unity 自动化测试的高级 Gameplay Engineer / Technical Designer。请在本仓库中将**便携烘干机 PortableRockDryer** 与 **吸盘 SuctionGrip** 作为可玩、可测试的功能道具实现，并保留现有 ClimbingTest 全部正常功能。

**最高优先级资料**：
1. 本次用户确认的设计稿 `Docs/PEAK_NewProps_GDD_V1.0.md`（所有【已定】规则不可擅改）；
2. 本任务 Prompt；
3. 仓库内 `AGENTS.md` 及 `.agents/skills/peak-items-unity/SKILL.md` 的工程规则；
4. 现有代码、场景和实际测试结果，用于判断如何集成，而不是替代已确认需求。

这个工程是原创 PEAK 风格玩法原型。**不要假设获得了 PEAK 正式游戏的源码、网络 API 或资产授权**，也不要复制/修改专有资源。若仓库仅有单机 ClimbingTest，就先完成真正可玩的单机体验，并通过可替换的权威命令接口隔离未来多人集成；不得把“模拟多人接口”标为“多人同步完成”。

**原则**：先审计、后增量开发；最小侵入、逐阶段验证；不覆盖用户手调的 `ClimbingTest.unity`、Mini Peak、8m/18m 测试墙、材质、摄像机/体力调参；不运行历史重建场景的 Tools 菜单；不写死 `Assets/PhysicsPrototype/`。全部资源路径以仓库实际目录为准（历史上通常是 `Assets/Scripts`、`Assets/Editor`、`Assets/Audio`、`Assets/Scenes`）。不要改造题目一的 ActiveRagdoll。

## 2. 锁定的设计数据（不可擅改）

### 2.1 两件道具共通

- `E` 拾取；手持 `LMB` 使用；`Tab` 收入正常物品槽（有空位时）；Backpack 走已有独立存取交互；`Q` 短按丢弃、长按蓄力投掷（使用项目既有时长/力度曲线与上限）。
- 每件重量固定、占 **1 格**、可放入 Backpack。手持/存储/丢弃/拾起不重置使用次数或唯一实例 ID；物品的 world entity、背包状态、HUD 要一致。
- 对非法目标/距离/没有作用对象/输入冲突/被暂停/失败请求：**不扣使用次数，不施加效果**，明确给出原因。

### 2.2 便携烘干机

- `ItemId=PortableRockDryer`，重量 **5**，使用次数初始 **3**、上限 **3**。
- 瞄准湿滑岩面按下 `LMB`，成功一次 -1；长按不重复使用。
- 以命中点为中心，对连通岩面作 **7m×7m**（局部展开宽/高各 7m，半宽 3.5m）覆盖，总有效展开面积不得因为分支复制超过约 **49m²**。允许跨内外转角，禁止跨空气间隙、穿实体薄墙烘干背面。不得仅用一个世界空间 OverlapSphere 代替连通性。
- 立即移除有效区湿滑减益，持续 **20 秒**；重叠合法使用刷新被覆盖单元的失效时间为 `now+20s`，不叠加多层增益。到期交回天气/湿度系统控制：持续下雨则恢复湿滑，雨停则遵循现有环境规则。多人共享同一世界地形状态。
- 无湿面且无可合法刷新的活动干燥片区，则不扣次数。有效使用导致剩余次数 0 时立即移除道具，但既有干燥区仍持续到期。
- 已点燃且可交互篝火：余次 **1 或 2** 时，充能 `min(3, current+2)`，同一 **道具实例 ID × 篝火实例 ID** 最多成功一次。满 3、未点燃、距离不符或历史重复充能，不扣机会；道具 0 次已销毁无法充能。历史记录跨丢弃、存取、转让保留。
- 使用射程、表面离散精度属【待调优】；建议先可配置 5m，绝不能将其写为不可修改的策划定值。

### 2.3 吸盘

- `ItemId=SuctionGrip`，重量 **3**，初始/最大 **15 次**，可放 Backpack。
- 手持状态下，按住 `LMB` 在合法普通/倒悬/头顶岩面**成功建立新吸附会话时**消耗 1 次；失败不扣。长按期间原地挂住、WASD 移动、内外转角或竖墙→顶面连续转场都属于同一会话，不重复扣次数。
- LMB 松开立即脱附并按现有 Rigidbody 重力下落；外力/死亡/表面失效也结束会话。余次从 1→0 的最后会话必须继续有效，**会话结束后**才销毁道具。
- 静止且仍合法吸附时按照当前角色普通静止/走路体力恢复速率恢复，但**本次会话实际累计恢复最多 20 点**，不突破动态有效体力上限。移动时按正常攀爬/快爬消耗体力；本次已恢复额度不能通过转角、停止/移动切换、视角变化或再次进入 SuctionResting 重置。
- 唯一允许“手持本体时攀爬”的特殊物品。普通手持物不能因此获得抓墙权限。允许从已有普通攀爬通过快捷物品槽进行安全抓握交接；合法才扣次，切换过程不能出现免费体力/穿墙/无故坠落。
- 可抓 `SuctionAllowed` 的实体岩面，支持墙→天花板/倒悬→另一墙的碰撞安全运动（持续同次会话）；不支持未标记装饰物/空气/道具/角色或强制不可抓的悬石。镜头保持世界重力上方向，不允许瞬间翻转 180°。

### 2.4 不做的东西

- **不实现跳床**；不添加第三件道具、不重写整个 ClimbingTest、不更改原来 Q/T 道具的能力、不擅自修改已定数值、不引入新天赋或永久体力强化。
- 如缺乏多人系统，不能仓促引入全新网络框架替换现有单人程序；明确“单机权威实现、多人适配接口、多人实测 NOT RUN”的区分。

## 3. 推荐架构（名称可因仓库而异，保证职责）

### A. 数据层与库存兼容

- `ItemDefinition` (ScriptableObject)：类型、重量、最大次数、槽位、图标、可否 Backpack、特殊手持攀爬权限。
- `ItemInstance` / `ItemRuntimeState`：稳定 `Guid`、当前次数、持有者、所在槽、已用篝火 GUID 列表、消耗状态。**实例状态不能存在共享的 ScriptableObject 定义资产内**。
- `IItemInventoryAdapter`：映射已存在的 E/Q/Tab/Backpack/负重；若仓库只有 E 拾取，优先最小增量补齐必需的单机物品槽，并保留旧拾取系统，不能覆盖原有 `PhysicsItemCarryController` 的正常能力。
- `IItemCommandGateway` / `IItemAuthority`：`UseDryer`, `RechargeDryer`, `BeginSuctionSession`, `EndSuctionSession` 统一返回 Success/FailureReason 和序列号。当前单机用 LocalAuthority；以后能替换网络端。
- **幂等**：每个成功使用/充能附唯一请求 ID、检查所有权与当前状态，重复执行不会重复扣次/加次数。

### B. 湿岩、天气与烘干

- `IRockWetnessProvider`（原始潮湿状态及玩法减益）+ `TemporaryDryOverride`（临时覆盖，计时结束删除）；不能直接永久改写原本湿度数据。
- `RockSurfaceGraph`：可缓存表面片区和邻接边（包括 90° 内外角、岩壁前后两面但仅真实连通时有边），每个片区可寻址并标记岩石材质/可烘干/可吸附。
- `DrySurfaceAreaResolver`：命中点→连通展开→在 7×7 预算内得到离散作用片区/采样单元列表；可视化 Debug Mask、边长/面积统计；薄墙背后默认无跨面邻接，不能透墙。
- 若缺少 PEAK 原版天气，在演示场景新增简易可开关雨天/湿滑测试桩，并保持接口可替换；严禁假装已有完整动态天气系统。
- 计时以权威时钟为准，暂停期间依据项目暂停语义冻结单机计时；网络场景将时间戳接入服务端时钟。

### C. 吸盘物理攀爬

- `SuctionUseController` 管理 LMB/会话/扣次/预算/销毁，`SuctionSurfaceProbe` 判断目标，`SuctionMovementAdapter` 复用当前 PhysicsClimber Rigidbody 动力学、碰撞、转角等模块。
- 物理胶囊与视觉模型/头部/镜头分离，**不能对 `CharacterVisualRoot` 累计乘旋转造成后仰翻转**；不能直接 Transform 穿墙移动物理胶囊。
- 表面局部坐标在竖墙和顶面连续构造；始终由表面接触几何确定抓附，不通过角色摄像机或面向强制判定。
- 对天花板路径使用 CapsuleCast / Overlap 等验证真实容积；目标占用不足、超距、目标不是实体岩石时不得入会话。摄像机仅做表现，不能改物理 Collider。
- 维持并尊重现有“LMB 失败不消耗体力、成功抓附才耗体力”的普通状态；吸盘恢复作为明确的**特殊状态覆盖**，不可全局修改普通攀爬规则。

### D. UI/音效

- 共享 HUD 显示手持道具、3/3 或 15/15、失效原因、合法/非法准星；烘干区显示20秒剩余时间；吸附区显示 `本次恢复 +n/20`、最后一次会话将销毁。
- 使用成功事件触发 SFX/VFX，不依赖下一次轮询才播放；避免过去项目发生的抓附/落地声音慢半拍问题。资源可先使用原创占位，不假设有官方 PEAK 素材。
- 不得抢占 Start/Pause/Resume/Exit 菜单的鼠标和按键焦点；暂停期间无有效道具操作或次数变化。

## 4. 分阶段实施（每阶段必须验证并写报告）

### Phase 1 — 基础接口与测试替身

创建或复用物品实例/库存/权威命令接口，完成实例唯一 ID、重量、格子、背包适配、可抛物和使用次数的最小链路，保留旧道具。缺少天气/篝火则建立独立测试替身。先写关键 EditMode Tests：计次、唯一性、实例身份、失败不扣次、暂停阻断。**不要先制作复杂 VFX 或大规模改 Scene**。

### Phase 2 — 便携烘干机

实现射线合法目标、连通岩面图、7×7 表面展开、范围预览、雨天临时覆盖 20s、重叠刷新、次数消耗/销毁、篝火 +2（1/2 次）、同实例×同篝火唯一性。提供运行时 Debug 面片图、受影响单元和无效原因。对面积、薄墙、非连通缝隙、雨停/雨中到期编写自动测试；场景演示中可目视识别区域。

### Phase 3 — 吸盘

实现合法岩面吸附、15 次会话记账、单次恢复预算20、移动耗体力、最后一次延迟销毁、手持例外、普通攀爬交接；竖墙→头顶→竖墙连续轨迹与碰撞安全（同会话）；鼠标和镜头行为不破坏相机限位。针对会话计数、预算、无效目标、冲击脱落、碰撞与相机做 PlayMode 验证。

### Phase 4 — 交互与内容整合

将两个道具放入现有 `ClimbingTest` 的**独立新增测试组**，不移动原墙体、不重置 Mini Peak 和体力/镜头 Inspector 值。添加供调试的湿岩转角、薄墙背面、篝火、倒悬岩廊。修复 E/Q/Tab/LMB 的优先级冲突，验证用户原有 `Q/T` 两件道具与新道具共存，Pause 时绝无意外扣次。

### Phase 5 — UI、音频、视觉及性能

增加占位模型、准星、次数 UI、倒计时、异常提示、音频即时反馈。确认干燥计算仅在使用时查询并缓存拓扑，不每帧扫描所有 Mesh；记录面积采样误差、极端岩面下的查询耗时；调参字段可序列化。人机交互需以 Play Mode 录像和实际输入验证。

### Phase 6 — 网络兼容与终验

若现有项目确有网络框架，才依现有架构集成权威使用、世界湿岩同步、多人吸附、交换物品与断线重连；必要时开展 2/4 人测试。若没有网络框架，仅交付可替换 `IItemAuthority`、稳定实例 ID 和重复请求模拟测试，并把**真正网络同步标记为 NOT IMPLEMENTED**，不能假称完成多人联机。

创建 `Docs/ITEMS_IMPLEMENTATION_STATUS.md`、`Docs/ITEMS_TEST_REPORT.md`、`Docs/ITEMS_CHANGELOG.md`，逐项标记 P0/P1 完成度。

## 5. 必须自动化的验收断言（与正式策划案 QA 编号一一对应）

**烘干机**：成功 3→2；长按不重复；无效目标0扣；L型墙合法跨角且薄墙背面/空隙不传递；7×7 限制不因 Y 分支重复；雨中20秒后恢复、雨停遵从自然状态；重复烘干刷新不叠层；1→0 道具销毁但区域继续；篝火 1→3、2→3、3 不充、同设备×同篝火仅一次，丢弃/交易/存背包历史不重置。

**吸盘**：合法 15→14；无效0扣；保持 LMB、不移动不再扣次且静止最多恢复 +20；先恢复8→移动→再静止最多再12；按住不变方向/跨角/进顶面不重复计次；移动正常消耗；最后1→0会话继续、松手后删除；无效悬石禁止吸；转场通过真实胶囊扫掠；LMB 松开及时坠落；普通手持物仍然不能获得吸盘例外；吸附时切换/放下不导致刷次数。

**系统**：普通攀爬、内外转角双面、上翻、8m/18m 落地、镜头起始位/±80°限位、奔跑/体力、原道具、E拾取、Start/Pause/Resume/Exit 全部回归。对未实现的网络功能提供明确的 NOT RUN / NOT IMPLEMENTED，而非虚构测试。

## 6. Unity 实际验证与输出格式

- 确认 `Packages/manifest.json` 中有 Test Framework；在 Editor 手动可运行 EditMode/PlayMode；若可获取 Unity.exe，关闭占用同一工程的 Editor 后调用 `-batchmode -runTests -testPlatform EditMode` 与 `PlayMode`，写日志/XML，并解析结果；只返回码0不能证明全部测试通过。
- 必须说明本地 Unity 版本、实际运行的测试数与失败清单。没有 Editor 或许可证时保留测试源码，标 `NOT RUN (Unity Editor unavailable)`。
- 对场景资源使用幂等 Editor 安装工具；再次执行不能复制对象、重置原物体 Transform 或重新生成 ClimbingTest 场景。
- 每个 Phase 输出：`DONE/PARTIAL/BLOCKED`、变更文件、接口/Scene 影响、测试 `PASS/FAIL/NOT RUN`、剩余风险、回滚方法。确保稳定阶段可提交独立 Git commit；不要用强制 reset 破坏原有数据。
- **完成定义**：单机 P0 全部真实可玩、可见 UI、可自动化验收；新的场景演示是可加载的 `.unity` 场景或原场景中新增的独立对象组；新道具从拾取到最终消耗闭环；其它旧玩法无回归。
